# Proxmox VE LXC / QEMU Console API Token Support Guide

## Background & Root Cause

When integrating external web panels (like **InterDash**) with **Proxmox Virtual Environment (PVE)**, connections to interactive container or VM consoles are handled via **`proxmox-termproxy`**.

1. The control plane calls `POST /api2/json/nodes/{node}/lxc/{vmid}/termproxy` authenticated via a Proxmox API Token (`PVEAPIToken=root@pam!interdash=...`).
2. Proxmox starts `/usr/bin/termproxy` listening on an ephemeral port (e.g. `5900`) and signs a short-lived VNC ticket.
3. The control plane connects to `GET /api2/json/nodes/{node}/lxc/{vmid}/vncwebsocket` and performs the terminal handshake by sending `<user>:<ticket>\n`.
4. `proxmox-termproxy` connects internally to `POST /api2/json/access/ticket` on `localhost:85` (`pvedaemon`) to validate the ticket against the user identity.
5. In stock Proxmox VE (PVE 7.x through 8.x+), `PVE::API2::AccessControl::create_ticket` calls `lookup_username($username)`. Because `lookup_username` only permits `<username>@<realm>` (and strictly disallows the `!` token separator), Proxmox throws:
   ```
   authentication failure; rhost=127.0.0.1 user=root@pam!interdash msg=value 'root@pam!interdash' does not look like a valid user name
   ```
   Consequently, `proxmox-termproxy` terminates the connection immediately, causing WebSocket close code `1006` in the browser console.

---

## The Solution

The patch updates `/usr/share/perl5/PVE/API2/AccessControl.pm` in `create_ticket` to cleanly inspect the username for token syntax via Proxmox's built-in `PVE::AccessControl::split_tokenid($username, 1)`:
- When a token ID (e.g. `root@pam!interdash`) is present, it validates the owning user (`root@pam`) and checks token existence (`interdash`).
- It retains the full token ID for `verify_vnc_ticket`, matching the VNC ticket generated by `POST /termproxy`.
- Standard user logins (e.g. `root@pam` or Proxmox Web GUI) are completely untouched.

---

## One-Click Hypervisor Patch

To apply this fix on any Proxmox VE node, execute:

```bash
curl -fsSL https://raw.githubusercontent.com/xRosieRose/InterDash/main/scripts/patch-pve-termproxy.sh | bash
```

Or from within a cloned InterDash repository:

```bash
bash scripts/patch-pve-termproxy.sh
```

### Automatic Persistence Across PVE Updates
The script automatically configures an APT post-invoke hook at `/etc/apt/apt.conf.d/99pve-termproxy-token`. Whenever `pve-manager` or `libpve-access-control` packages are upgraded via `apt dist-upgrade`, the patch is automatically re-applied without manual intervention.
